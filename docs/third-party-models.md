# Third party models and textures

What is in the game that somebody else made, and under what licence.

**As of wave P (2026-09-21) the answer is: nothing.** Every mesh in
`Arena/assets/parts/**` is generated by this repo's own Python in
`Tools/blender/**`, and every texture in `Arena/assets/textures/**` is generated
from a Recraft image through this repo's own `Tools/textures/make_pbr.py`. This
file exists so that stays true on purpose rather than by accident, and so the
survey behind it does not have to be repeated.

## The rule

A third party asset may ship in Roboteer only when all four hold:

1. the licence is CC0, or CC-BY with attribution we can actually give;
2. the licence is the one on the **download page we used**, not one quoted
   second hand (see Quaternius below, where those two now disagree);
3. the asset reaches `docs/graphics-bar.md` -- showroom PBR, real materials,
   chunky readable silhouettes on a 6.9 inch OLED -- **without** being redrawn;
4. the credit and the licence go in the table at the bottom of this file, and
   the licence text goes in `Art/licences/<source>.txt`, before the asset is
   committed.

Failing 3 is the usual outcome and it is not a close call: almost every free
3D asset pack aimed at games is flat-shaded cartoon low poly, which is a
different art direction, not a lower budget version of ours.

## The survey (2026-09-21, wave P, agent E)

The owner asked, in these words: *"where possible see if there are good existing
3d models online we can freely use"*. Thirteen parts were in scope: six weapons
(shock prod, tesla arc, drill lance, twin saw, napalm cannon, vortex spinner),
three drives (legs, hover, adaptive tracks), one chassis (apex), one utility
(overcharge core) and two armour faces (reinforced, reactive) which are
materials rather than meshes.

**Result: 0 of the 13 could use a free asset.** What was checked and why each
was rejected:

| source | licence as published | what it actually has | verdict |
|---|---|---|---|
| **Kenney** | CC0 1.0 | no robot or combat-machine pack at all; the sci-fi packs are flat-shaded cartoon kits | nothing to use |
| **KayKit / Kay Lousberg** | CC0 1.0 | fantasy dungeon and character kits, plus one cartoon sci-fi pack | wrong genre and wrong art direction |
| **Quaternius** | **disputed, see below** | Animated Mech Pack (4 humanoid mechs), Animated Tanks (4), Steampunk Turret pack; all cartoon low poly with flat colour | geometry reference at best, and the licence is not safe |
| **Poly Haven** | CC0 1.0 | HDRIs, tileable materials, props. No robot parts | nothing for the meshes |
| **ambientCG** | CC0 1.0 | tileable PBR metal and plate materials | plausible for the two armour faces; not used, see below |
| **OpenGameArt** | mixed CC0 / CC-BY / GPL | per-asset licences, mostly low poly, quality very uneven | nothing at the bar |
| **Sketchfab** (CC0 filter) | per asset | scanned and hand-modelled props; a robot-combat part at this bar was not found under CC0 | nothing to use |

### The Quaternius licence, which is the finding worth keeping

Quaternius's pack pages still say CC0, but the site now carries a custom
**"Quaternius Asset License v1.0"** which forbids redistributing the raw
assets. Those two statements contradict each other, and a contradiction is not
a licence we can ship an App Store binary on. **Do not use Quaternius assets in
Roboteer** unless and until the site is unambiguous, and if that changes, take
the licence from the page the file was downloaded from on the day it was
downloaded, and put a copy in `Art/licences/`.

### Why ambientCG was not used for the two armour materials

ambientCG is genuinely CC0 and genuinely at the bar, so this one was a real
choice rather than a rejection. It was not used because the rest of
`Arena/assets/textures/**` comes through `Tools/textures/make_pbr.py`, which
does three things to a source image that a downloaded set has already had done
to it differently: it divides out the generator's baked lighting, it evens out
local wear density, and it mirror-blends the wrap band to a measured seam delta
of exactly zero (`docs/graphics-textures-notes.md`). Mixing one set that has
been through that with one that has not is how two plates on the same machine
stop looking like they were made in the same factory. The two new sets were
therefore generated the same way as the other eleven: a Recraft material photo
through `make_pbr.py` with the numbers recorded in `docs/wave-p-e-notes.md`.

This is a decision to revisit, not a law. If a future part needs a material
this pipeline cannot produce, ambientCG is the first place to look, the licence
is clean, and the only work is matching the flatten and seam treatment.

## Wave A materials (2026-09-24, materials lead)

Still nothing third party. The wave A master texture sets (`painted/painted_surface`,
`brushed_steel`, `scratched_titanium`) are generated from seeded noise by
`Tools/textures/make_masters.py`; the machine decals in `Arena/assets/textures/decals/`
are drawn by `Tools/textures/make_decals.py`. ambientCG and Poly Haven were not needed:
the look the owner asked for lives in roughness and the clear coat, not in photographed
detail, and a procedural FFT set tiles with an exact zero seam.

The decal lettering is set in **Barlow Condensed ExtraBold** (SIL Open Font License 1.1),
which already ships in `Arena/assets/fonts/` and `Roboteer/Fonts/` for the interface.
Rasterised glyphs in artwork are output of the font, which the OFL permits without
restriction; no font file is added by this. Every stencil mark (KESTREL WORKS, TORQ-9,
LIFT POINT, HIGH VOLTAGE, NO STEP) is invented; none imitates a real manufacturer.

## Tools, which are not assets

These are used to *make* what ships; none of them ships:

- **Blender 4.5** (GPL) at `~/Applications/Blender.app`, run headless from
  `Tools/blender/build_parts.py`. No Blender code or asset is redistributed.
- **Recraft** (recraftv4_1_raster), used to generate the source material photos
  in `Tools/textures/sources/`. Generated images, commercial use permitted under
  the Recraft terms the account holds. The prompt behind each is recorded in
  `docs/graphics-textures-notes.md` and `docs/wave-p-e-notes.md` so any of them
  can be regenerated.
- **Godot 4.6** (MIT) and **SwiftGodotKit**, which are dependencies, credited
  where dependencies are credited and not here.
