Figures: Saira with tabular figures

Decision 7 of 30 September: B612 Mono's fixed pitch put a full cell after every point, colon and comma ("89. 5 kg", "2: 58", "1, 200", "3. 1" on the judges card). Every figure in the app and the fight feed is now the UI face, Saira Semi Condensed 700, with its tabular figures switched on. B612 Mono is gone from the app and the pack. Branch wave-d-figures.

The face and why

  • Saira itself, not a second family. The Saira Semi Condensed files we shipped were Google Fonts' static v0.072, which has no tnum. The family's current release (Omnibus-Type/Saira v1.101, the source Google Fonts builds its variable Saira from) has tnum, lnum and pnum, the same vertical metrics and widths within half a percent. Both static files were swapped for the v1.101 ones, unmodified, OFL 1.1 with no reserved name in that release.
  • Figures = the label face with tnum on. Swift: BroadcastType.figureFont adds the OpenType feature to SairaSemiCondensed-Bold. Godot: Broadcast.font_numerals() is a FontVariation over the label file with tnum. Every digit is 0.553 em, so a counting clock never jitters; the point and colon keep their own 0.27 em.
  • Same height as before. Figures draw at 1.09 times the mono's size, the size at which Saira's figures stand exactly as tall as B612's did. Digits come out 7 % narrower than the mono's cells, so no string got wider. Saira's line box is taller than the mono's, so figures-only lines (score bugs, scrap, judges' scores, payout rows, title block cells, stat footers) are trimmed back to the mono's box with figureLine; a figure inside a sentence is set at the words' own size.
  • B612 Mono did not earn a place. The app has no part codes; its only code-like use was the menu's "02 / 03 / 04" row numbers, which read the same in Saira. Removed from both bundles: 139 KB per copy out, 33 KB per copy in for the newer Saira files, about 0.21 MB smaller over app and pack.
